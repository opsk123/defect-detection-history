1. 최종 운영 대상
최종 2단계는 GitHub Pages 웹앱 하나로 통일한다.
주소: https://opsk123.github.io/defect-detection-history/
기존 저장소: https://github.com/opsk123/defect-detection-history
배포: main 브랜치 /docs → GitHub Pages
Google 로그인 구현 배포 커밋: 81687097f3034818c6891920e05be975d19579f3

로컬 Streamlit(http://127.0.0.1:8501)과 과거 ChatGPT Sites는 최종 운영 사이트가 아니다.
기존 파일과 데이터는 삭제하지 않고 보관했다.

2. 요청 조건별 적용 결과
[적용] 기존 GitHub 저장소를 통한 웹 배포: Pages 배포 성공 확인.
[적용] Supabase 연결: ygnynrpcismszflhysqr / analog-flow-guard 프로젝트의 수집 RPC 연결 확인.
[적용] 누적 저장: 1단계가 저장한 판정 이벤트가 Supabase accc_events에 계속 추가되고 웹 조회에 반영된다.
[적용] Google 로그인: provider 활성화, Google OAuth PKCE 화면 배포, 실제 배포 사이트에서 Google 계정 로그인 화면 이동 확인.
[적용] 비로그인 조회 차단: Google 조회 RPC의 무인증 요청은 HTTP 401.
[적용] 기존 공용 비밀번호 폐기: 006 마이그레이션 적용, 기존 비밀번호 조회 RPC의 무인증 요청도 HTTP 401.
[미확인] 실제 사용자 계정으로 Google 동의와 콜백을 완료한 뒤 기록 조회까지 성공했는지는 사용자의 최초 로그인이 필요하다.
[대기] 관리자 지정: GitHub 소유자 opsk123의 Google 이메일을 아직 확인받지 못했다. 현재 관리자는 0명이며 신규 로그인은 모두 조회 전용이다.

3. 저장 구조와 조회 기준
1단계 검출 프로그램 → 로컬 영속 기록 및 전송 대기열 → Supabase 누적 이벤트 → 2단계 조회 화면.
검증 시점 Supabase 원본 이벤트: 23,950건. 이는 검사 세션 수나 사진 수가 아니라 이벤트 수다.
화면의 검사 기록 한 줄과 검사 세션 수는 run_id 기준이다.
기본 조회는 최근 30일이며 시작일을 변경하면 더 오래된 누적 기록을 조회할 수 있다.
한 번의 조회 제한 20,000건은 화면 조회 한도이며 데이터 삭제·보존 한도가 아니다.
가상 시연 데이터는 fixture로 구분하고 포함 여부를 선택할 수 있다.
원본/보정 사진 파일은 1단계 PC에 보관한다. Supabase에는 점수·분류·검출 좌표·메타데이터가 누적된다.
네트워크 장애 시 로컬 전송 대기열을 유지하며 자동 전송 설정이 켜져 있으면 재시도한다.

4. 사용자 권한
일반 Google 로그인 사용자: 검사 기록·검토 메모 조회, 필터, 상세, CSV 다운로드.
관리자: 소유자로 확인된 Google 계정 한 개를 서버 UUID로 지정한 후 검토 메모 작성·수정 가능.
모델 원본 판정이나 수집 원본 이벤트를 이 웹에서 수정하지 않는다.
관리자 권한은 브라우저 표시가 아닌 서버 RPC에서 검사하며 메모 변경은 감사 기록을 남긴다.
첫 로그인 사용자에게 관리자 권한을 자동 부여하지 않는다.

5. 실행 방법
1단계: 작업 폴더의 start.bat 실행.
2단계: 작업 폴더의 start_dashboard.bat 실행 또는 최종 운영 주소 접속.
start_dashboard_online.bat와 1단계 클라우드 메뉴의 결과 보기 링크도 같은 GitHub 주소를 연다.
start.bat --dashboard 역시 최종 GitHub 사이트를 연다.
기존 로컬 Streamlit이 별도로 필요한 경우에만 start_dashboard_legacy.bat를 사용한다.

6. 검증 결과
- 기존 세션 집계 및 CSV 테스트 통과.
- 로컬 PostgreSQL/PGlite 권한 검증: 비로그인 차단, 일반 사용자 수정 거부, 권한 사칭 거부, 지정 관리자 저장 및 감사 기록 통과.
- 브라우저 검증: Google OAuth 요청, JWT 조회, 관리자/일반 사용자 UI 구분, 메모 저장, 로그아웃 시 기록 제거 통과.
- 운영 페이지: Google 로그인 페이지 및 SDK 정상 제공, Google 계정 로그인 화면으로 이동, JavaScript 오류 없음.
- 서버: 005 권한 스키마 및 006 비밀번호 RPC 차단 적용 완료.
- 일반 사용자/관리자의 실제 Google 로그인 완료 검증은 계정 소유자가 직접 수행해야 한다.

7. 남은 최종 확인
최종 사이트에서 Google로 로그인한다.
관리자에게 연결할 Google 이메일을 확인한 뒤 서버 SQL에서 해당 Google 사용자 UUID를 관리자 한 명으로 지정한다.
소유자 메모 수정 성공과 다른 Google 사용자 수정 거부를 실제 계정으로 확인한다.
Google에서 리디렉션 오류가 발생하면 GOOGLE_LOGIN_SETUP.md의 콜백 URL 및 Supabase 허용 URL을 확인한다.
